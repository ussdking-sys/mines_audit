# Provably Fair — Concepts & Verification Guide

> This document explains what "provably fair" means, how BC.Game implements it,
> and how to use this tool to verify your rounds.

---

## What is Provably Fair?

A provably fair system is a cryptographic commitment scheme that allows players
to verify that a game outcome was determined before they placed their bet — and
was not altered after.

The key principle: **the house cannot change the outcome after you commit**.

---

## How BC.Game's System Works

### Before the game

1. BC.Game generates a random `serverSeed`
2. Computes `SHA256(serverSeed)` — the "server seed hash"
3. **Publishes** the server seed hash in your Seed Setting panel
4. Keeps the actual `serverSeed` secret

Because the hash is published *before* you play, the server cannot change
the seed after seeing your bets — changing the seed would change the hash,
and you'd detect the mismatch.

### During the game

5. You provide a `clientSeed` (your own random string — you can customise it)
6. A `nonce` tracks how many bets you've made with this seed pair (starts at 0)
7. The board is derived as:
   `HMAC-SHA256(serverSeed, clientSeed:nonce)`

### After the game (seed rotation)

8. When you rotate seeds, BC.Game **reveals** the previous `serverSeed`
9. You can now verify: `SHA256(revealedServerSeed) == publishedHash`
10. Re-derive the board and confirm it matches what was played

---

## How to Find Your Seeds on BC.Game

1. Go to `bc.game/game/mines`
2. Open the **Seed Setting** panel (usually a dice/settings icon)
3. You will see:
   - **Server Seed (hash)** — the published commitment (e.g. `a24883b544...`)
   - **Client Seed** — your current seed (e.g. `e08765ff55cc72c1b02...`)
   - **Nonce** — your current bet count (starts at 0)
4. To get the actual server seed: **rotate your seeds**
   - The panel shows the previous server seed hash in "Current seeds"
   - After rotation, the previous server seed is revealed in your history

## Verification with bc-mines-lab

### Single round audit

```bash
python main.py audit \
  --server-seed  "your_revealed_server_seed" \
  --server-seed-hash "the_published_hash" \
  --client-seed  "your_client_seed" \
  --nonce        0 \
  --mines        3
```

### Commitment check only

```bash
python main.py verify \
  --server-seed      "your_revealed_server_seed" \
  --server-seed-hash "the_published_hash"
```

---

## What Provably Fair Does NOT Guarantee

- It does not remove the house edge — multiplier tables are designed to favour the house
- It does not make outcomes predictable before the server seed is revealed
- It does not prevent the server from simply not publishing a valid hash
- It relies on you checking the hash *before* the game, not after

## Glossary

| Term | Definition |
|------|-----------|
| `serverSeed` | Random string generated by BC.Game; kept secret during play |
| `serverSeedHash` | `SHA256(serverSeed)`; published before your bet; proves commitment |
| `clientSeed` | Your contribution to randomness; you can customise it |
| `nonce` | Bet counter for this seed pair; starts at 0; increments each bet |
| `HMAC` | Hash-based Message Authentication Code; combines both seeds |
| Commitment | Publishing a hash before the outcome prevents seed tampering |
| Verification | Confirming hash and re-deriving the board after seed reveal |
